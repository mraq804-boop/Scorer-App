# Team Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let one owner run a public team page — saved squad, fixtures, named seasons, player stats and leaderboards, Player of the match — fed automatically by matches scored in the app, with invited scorers.

**Architecture:** Squad players get permanent ids that a team match uses as its player ids, so the existing engine's per-player lines add up across matches; wickets gain an optional `fielderId`. On every sync the phone computes a small per-match `TeamMatchRecord` (raw figures + XI + outcome) with a pure function and pushes it on the match row; the public page aggregates those records with another pure function (`aggregateTeamStats`), never replaying balls. Team data lives in new Supabase tables written only through security-definer RPCs; the phone caches the team in Dexie v2 so team matches start offline.

**Tech Stack:** existing — Next 16.4.2, React 19.3, TypeScript, Tailwind 4, shadcn, Supabase (`@supabase/ssr`, `@supabase/supabase-js`), Dexie 4, vitest + PGlite + fast-check, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-27-team-page-design.md` (read it first; this plan argues from it). Existing system: `docs/ARCHITECTURE.md`. Conventions from the launch plan `docs/superpowers/plans/2026-10-23-score-and-share.md` still apply.

## Global Constraints

- Branch `feat/team-page`. Never commit `.env.local`; only Task 10 touches `.env.example` (placeholders only). Stage files explicitly (no `git add -A`).
- The engine (`src/lib/scoring/**`) stays pure (no DOM, Date, Math.random, crypto, no imports outside it, no English). The only engine change is the optional `fielderId`; every existing engine, golden and property test must still pass unchanged.
- New pure team logic lives in `src/lib/team/**` under the same purity rules (it may import `@/lib/scoring`; no English — copy lives in `src/lib/i18n`).
- Events stay append-only; never lose a ball; the team feature never blocks scoring (no cached team → plain typed-name match).
- No `SUPABASE_SECRET_KEY`. All new writes go through `security definer set search_path = ''` RPCs with `revoke execute … from public, anon, authenticated` then explicit grants; no table write privileges for `anon`/`authenticated`.
- Public team pages (`/t/**`) never sign in and their client bundle must not import Dexie, sync, identity, Turnstile, `src/components/scoring/*` or supabase-js.
- `/`, `/new`, `/score` stay statically rendered shell pages with `<GuestSession/>`/`<PwaRegister/>` per page and no `next/dynamic`/dynamic `import()`. `/team`, `/team/join`, `/t/**` are network pages (not precached).
- All UI copy via `t()` (`src/lib/i18n/en.ts`); names in `<bdi>`, truncating; direction-neutral Tailwind only (no `ml-/mr-/pl-/pr-/left-/right-/text-left`).
- Exact numbers from the spec: averages need ≥ 3 innings; strike rate ≥ 30 balls; economy ≥ 10 overs (60 legal balls). Points: 1 per run, +1 per four, +2 per six; +10 for 30–49, +20 for 50+ (milestones not cumulative); 20 per wicket, +10 per maiden, +1 per dot ball; 10 per catch, run-out or stumping. Leaderboards show top 5. Team time zone default `Asia/Karachi`. Invites expire after 7 days.
- Quotas (free tier): ≤ 60 squad players, ≤ 300 fixtures, ≤ 30 seasons, ≤ 10 scorers, ≤ 5 live invites per team; `player_stats` ≤ 16384 bytes; names ≤ 40 code points (team, player, opponent, season), ground ≤ 60, fixture notes ≤ 280.
- Ports: e2e/preview on 3200; never stop family-home's server on 3100. Backend e2e only with `E2E_BACKEND=1`.
- Commits: imperative plain English ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Checks after every task: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` (placeholder env from `.claude/launch.json`), plus the Playwright specs the task names.

## Review Focus

1. **A squad player whose row hasn't reached the server yet** (added offline at the ground; the match synced first) — the team page must not crash or drop the match; that player's figures appear once the squad row lands. → Task 2 test `ignores player ids missing from the squad`.
2. **A renamed or inactive squad player** — past figures stay under the same id and show the current name; inactive players stay on all-time boards. → Task 2 test `uses current squad names and keeps inactive players`.
3. **A match played near midnight on a season's last day** (team time zone vs UTC) lands in the right season. → Task 2 test `assigns seasons in the team time zone`.
4. **A scorer removed while they still have an unsynced team match** — the match must still sync (never lose a ball), just no longer linked to the team. → Task 3 test `a non-member's team match syncs unlinked`. (Plan decision: the spec's "pushing a team match as a non-owner is rejected" is implemented as *accepted but not linked to the team*, because rejection would strand the scorer's balls on the phone.)
5. **Outcome from the team's side** — the team batting second and winning, defending, tying, a hand-ended chase marked No result. → Task 2 tests for `teamOutcome` and the record.

```ts
export type LeaderboardKey = "runs" | "wickets" | "highest" | "sixes" | "fours" | "average" | "strikeRate" | "economy" | "bestBowling" | "maidens" | "dots" | "catches" | "runOutsStumpings" | "mvp" | "potm";

export type TeamRecord = { played: number; won: number; lost: number; tied: number; noResult: number };
export type TeamStats = { record: TeamRecord; players: PlayerTotals[]; leaderboards: Record<LeaderboardKey, LeaderboardRow[]>; potm: Record<string, { playerId: string; suggested: boolean } | null> }; // keyed by match code
```
Functions:
- `teamOutcome(result: Result | null, side: TeamSide): Outcome | null` (won when winner === side, tied for `tie`, else lost; null when no result).
- `matchRecord(state: MatchState, side: TeamSide, xi: string[], playedAt: string): TeamMatchRecord` — players = XI ids (each gets an entry); batting from the innings where `battingTeam === side`, bowling from the other; fielding counts dismissals in innings the team fielded by `out.fielderId`: caught → catches, run_out → runOuts, stumped → stumpings; `opponent` = `state.teams[other].name`.
- `matchPoints(p: PlayerMatchStats): number` with exported named constants for every value in Global Constraints.
- `seasonOf(playedAt: string, seasons: Season[], timeZone: string): string | null` — local date via `Intl.DateTimeFormat("en-CA", { timeZone })`; among seasons containing the date, the latest `startsOn` wins. (Intl is fine here — not the engine.)
- `aggregateTeamStats(matches: TeamMatch[], squad: SquadPlayer[], filter: { seasonId: string | null; seasons: Season[]; timeZone: string }): TeamStats` — counted matches = `status === "complete"` or `resultOverride === "no_result"`, with a non-null record; live ones excluded. Record: NR override → `noResult`, else by `record.outcome`. Only ids present in `squad` get totals (Review Focus 1). Averages/SR/economy null below the thresholds, and such players are left off those three boards. Ordering: value desc (economy asc; bestBowling by wickets desc then runs asc), ties by squad name asc then id. Each board sliced to 5. POTM per match: `potmPlayerId` override, else highest `matchPoints` among XI (ties: more runs, then name).
